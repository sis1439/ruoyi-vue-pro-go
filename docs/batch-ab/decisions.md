# 批次 A / B 决策记录

1. **版本与范围。** Go 采用交接基线 4a240b8；商城前端采用现有3c4bf38；Java及后台固定版本见baseline和前端报告。批次A的T01交付契约盘点、消费端样本和测试基线，完整页面端到端兼容属于D。保留独立单体商城，不写入健康业务库，不重写页面。
2. **数据库。** 实测 PostgreSQL16.10，而非示例PG15或系统默认psql客户端14。迁移采用固定 golang-migrate/v4 v4.18.3；SQL1..6前向迁移，发布后禁止修改。模型源独立导出有效列与映射，禁止将自动建表当作迁移；结构、索引、种子、页面菜单和交易标识约束分离。
3. **数据表示。** BitBool存smallint0/1，native bool存boolean；CSV、JSON、JSONB按原codec及真实驱动保留。金额使用整数分，保存与聚合测试覆盖超过32位的值。字段上游范围和业务算法的全面溢出审计不能由此推断完成。
4. **事务传播。** `repo.InTransaction`通过不可变context携带同一Query，嵌套服务加入已有事务；不修改共享Service连接。订单/项、SKU/SPU、券、积分余额/账本和本地支付单原子提交。单连接测试、真实数据库提交失败与SIGKILL验证该边界。远程支付请求不进入该事务。
5. **资源规则。** 下单扣减库存，未付款取消只恢复一次；优惠券条件更新，积分扣减锁定余额且不透支。未启用的活动与零元单明确拒绝；此阶段不将它们静默转为普通订单。支付成功/取消竞态、退款和远程通知留给C，未启用真实渠道。
6. **认证。** 商城独立JWT密钥来自环境，弱/占位/缺失配置启动失败；HS256+issuer+过期+iat+JTI+用户种类+access/refresh约束。Redis白名单是强依赖，故障拒绝。刷新使用一次性轮换，旧access失效；登出撤销关联令牌。轮换当前密钥会立即使旧签名失效，客户端重新登录；本期不引入多kid无感轮换。禁止与既有平台共用固定密钥。
7. **租户。** 已登录身份绑定租户且必须活跃；匿名商城通过服务端登记域名解析，请求头仅能在该域名的合法映射中选择。所有可修改业务表由模型租户字段和GORM统一检查约束；Raw/不安全关联查询拒绝，已使用的商品统计改为可验证模型查询。
8. **平台例外。** 不启用任意跨租户管理员写操作。启动时只读加载已按租户关联的RBAC策略并记录审计；另外提供显式目标租户的只读汇总检查接口，仅允许经数据库核实的保留platform_admin角色，记录操作者、来源租户、目标租户、操作和结果。该角色只能通过离线bootstrap显式初始化，普通角色/用户管理路径不得授予或接管它。不能放行visit-tenant-id。
9. **异步与缓存。** 后台任务从持久化job的租户恢复有时限context，不保留gin.Context；无租户拒绝。验证码/短信/限流/微信票据和文件路径显式限定租户；支付客户端缓存使用前重新校验渠道及应用。令牌缓存通过不可预测令牌键定位，再严格校验签名和租户记录，不能只凭键存在放行。
10. **文件与外部服务。** 本地文件用os.Root防目录和符号链接越界，租户元数据与路径双重检查。S3、微信/短信真实接入、上传终端兼容和生产运维属于后续T11/T13；无商户资料时不生成默认“成功”渠道。配置占位不属于真实联调证据。

11. **数据权限范围。** 首期使用租户内RBAC，不宣称实现部门/自定义/仅本人数据范围；不支持的范围配置必须拒绝，已有受限角色不得被解释为全部数据权限。
12. **租户缓存与审计。** 邮件和站内通知模板取消全局缓存，按当前可信租户查询；登录审计复制可信租户到有时限独立上下文；支付通知任务在调度上下文结束前完成当前有界批次，Redis锁按租户隔离并核对持有者后释放。通知DTO/成功协议/恢复仍由C完成。

本批次没有做真实支付、退款、短信发送、生产部署或远程推送。
